# Optimum Credit Design System

## Brand

- **Product name:** Optimum Credit (Optimum Financial Group)
- **Email chrome (`emailLayout`):** OFG wordmark logo + gold accent bar; footer legal name **Optimum Financial Group** (not “Optimum Credit Repair”). Staff progress-report alerts use card layout (severity + human type label + title/detail) — no raw `[alert_type]` dumps.
- **Default theme:** Dark on marketing site and client portal (`class="dark"` on `<html>`)
- **Admin panel:** Light by default; optional dark mode via sidebar toggle (`optimum-admin-color-scheme`)
- **Client portal:** Dark by default (brand); optional light mode via sidebar toggle (`optimum-portal-color-scheme`)
- **Portal progress PDFs:** Round-report taps use `deliverPdfBlob` — Web Share (Save to Files / Messages) on mobile when available, else open in a new tab, else `<a download>`. Errors surface as toasts (no silent failure).
- **Accent:** Gold `hsl(38 41% 58%)` — primary CTAs, rings, and highlights in dark mode
- **Background:** Deep navy / near-black (`#121829` theme-color)

## Admin form helpers

- `FieldHint` (`client/components/admin/FieldHint.tsx`) — one-line contextual note under a form control. `tone="muted"` (default, neutral), `"warning"` (`border-destructive/25 bg-destructive/5`), or `"accent"` (`border-primary/20 bg-primary/5`). Never use arbitrary colors (e.g. `amber-*`) for these — use `tone` instead.
- `EnumLegend` (`client/components/admin/EnumLegend.tsx`) — compact legend for enum selects (status, role, filter, etc). Pass `items` (`value`/`label`/`description`), the current `value` to highlight the active row, and an optional `title`.
- Copy for both lives under the `adminHelpers.*` i18n namespace (and `adminPipeline.*` for pipeline/case-specific copy) — always add new hint strings there in both `en` and `es`, never hardcode.

- `ClientStatusNotesCard` (`client/components/admin/ClientStatusNotesCard.tsx`) — pipeline client panel Overview: Pause / Block / Resume (reason required, quick-reason chips) + append-only staff notes (newest first, collapsible). Paused = `bg-secondary/60 ring-1 ring-border`; Blocked = `bg-destructive/5 ring-1 ring-destructive/30` with destructive Block button/confirm. Copy under `adminPipeline.*` (en + es).
- `ClientHoldBadge` (`client/components/admin/ClientHoldBadge.tsx`) — tiny pill for `paused` (muted) / `blocked` (destructive) clients; renders nothing otherwise. Used on pipeline Kanban cards (next to `LangBadge`) and the client panel header.
- Client status semantics: `paused` and `blocked` both stop all automated client messages (staff manual sends still allowed); `blocked` also locks portal login (`/portal/login?blocked=1` shows `clientLogin.accountBlocked`).

## Payment installments

Each installment has a **collection mode**:

- **Manual** — on the schedule only; admin marks paid later; no client `/pay` link
- **Payment link** — creates `/pay/:token`; client can pay via Authorize.net; admin can copy/generate the link
- **Already paid** — recorded paid at creation (`completion_source: manual`); no client notification or link

Surfaces: New Case schedule, Client panel Payment Schedule, Admin Payments splits tab, Calendar day panel (shared `AdminSplitActions`).

**Deduping:** Installments are keyed operationally by `(case_id, due_date, amount_cents)` — there is no DB unique constraint. Marking an **existing** row paid (UI / `update_payment_split`) never leaves a pending twin. Creating a **new** paid row while an open twin exists used to leave false overdue flags and double ledger entries; MCP `upsert_payment_splits` with `status=paid` and admin “Already paid” create now **update the matching open row** (or skip if already paid). Prefer `update_payment_split` when you know the `split_id`. For discounted Zelle/cash deals, prefer MCP `set_case_payment_plan` (`replace_open` default) so Pipeline balance matches the agreed total — not checkout coupons (`create_coupon` is for `/register` promo codes only). Client list `splits_amount_cents` excludes `cancelled` rows. `list_clients_owing` mode `overdue` includes past-due `pending` rows (no cron flips pending→overdue).

Hardened Twilio `recordings.list` pull when the in-memory buffer misses (cold start). Twilio Batch Transcription (Deepgram, English and Spanish) writes the transcript from the recording webhook.
