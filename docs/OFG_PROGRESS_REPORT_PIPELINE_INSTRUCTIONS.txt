OFG PROGRESS REPORTS — HOW TO USE THEM IN THE PIPELINE
======================================================

CONFIDENTIAL — for internal team use only.

This is the live CRM workflow (Client panel → Reports → Generate).
It replaces older Claude.ai Project Knowledge / external PDF setup guides.
See also: docs/OFG_PROGRESS_REPORT_TEAM_SETUP.txt


Think of every round as a “before → after” snapshot.

DEFAULT COMPARE MODE: BASELINE
  Every round’s Before = enrollment / Round 1 Before (day they started)
  Every round’s After  = the latest report for that round
  Scores + wins on the portal show lifetime progress vs enrollment,
  with an optional “this round” delta when it differs.

OPTIONAL: CHAIN MODE (escape hatch on Reports → Special / extended rounds)
  Round 1 Before  =  enrollment credit report
  Round 1 After   =  report after Round 1 work
  Round 2 Before  =  Round 1 After   ← auto-filled when chain is on
  Round 2 After   =  report after Round 2 work
  …and so on.

Baseline is the product default. Switch a case to Chain only when you
need round-to-round storytelling (e.g. mid-program reset). The wizard
reuses the matching Before PDF when available; re-upload Before only
if something is wrong.


WHERE TO OPEN IT
----------------
1. Pipeline → open the client panel
2. Reports tab
3. Tap Generate (OFG Progress Report Wizard)

You can generate once the case is in Docs Ready or any Round stage.
Compare mode (Baseline vs Chain) lives next to Max rounds under
Special / extended rounds — Save round settings to apply.


ROUND-BY-ROUND CHEAT SHEET
--------------------------

ROUND 1
  • Upload Before = enrollment / first baseline PDF (SmartCredit, etc.)
  • Upload After  = latest report for this round
  • Review scores, wins, targets, bureau tags (TU / EX / EQ)
  • Fix dates if the PDF date looks wrong
  • Preview → Publish
  • Client sees the report in their portal; pipeline advances

ROUND 2+ (BASELINE — default)
  • Wizard offers enrollment / Round 1 Before reuse when available — leave ON
  • Upload only the new After PDF
  • Override Before only if you must replace the enrollment file
  • Review → Preview → Publish

ROUND 2+ (CHAIN — optional)
  • Wizard offers: “Using Round N−1 After as Before” — leave that ON
  • Upload only the new After PDF
  • Override Before only if you must replace the prior file
  • If there is no published prior round: upload both Before and After
  • Review → Preview → Publish

The timeline strip on Reports shows each round’s score and report date
so you can see progress at a glance.


GOLDEN RULES
------------
✓ Prefer Baseline (vs enrollment) unless Chain is explicitly needed.

✓ Always publish Round N before starting Round N+1 when using Chain
  (reuse needs a published prior After).

✓ Compare the review screen against the source PDFs (open Before / After
  with the buttons). Low-confidence scores are flagged — fix them.

✓ Wins = items that disappeared. Targets = still on the report.
  Tap TU / EX / EQ badges to correct which bureau(s) apply.
  Portal shows since-enrollment wins primarily, plus this-round when dual.

✓ Report dates come from the PDF when possible; edit them if needed.
  They print on page 1 of the branded PDF.

✓ Check the CROA attestation before publish. Large score drops need an
  extra acknowledgment (usually a mis-read PDF — fix first).

✓ Reusing enrollment as Before on later rounds is correct in Baseline —
  that is how lifetime progress is measured.

✗ Don’t publish if Before and After look swapped (After date earlier,
  or scores collapsed for no reason).


QUICK FLOW (30 SECONDS)
-----------------------
  Open client → Reports → Generate
  → pick round
  → Baseline: enrollment Before (often reused) + new After
  → Chain Round 2+: reuse prior After + one new After
  → Continue → Run extraction
  → sanity-check scores / wins / dates
  → Preview → Publish


IF SOMETHING LOOKS OFF
----------------------
  • Wrong Before? Uncheck reuse and upload a different Before PDF.
  • Bad extract? Re-extract, or Start over and try again.
  • Resume a draft from the list at the top of the wizard.
  • Affiliates cannot run this — staff only.
  • Need round-to-round deltas only? Flip the case to Chain and Save.


That’s it: Baseline vs enrollment by default; Chain is the optional
escape hatch. The wizard reuses the right Before; you verify and publish.
